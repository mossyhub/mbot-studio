# Cooperative application migration contract

Keep installed OTA loader unchanged. New application is a self-contained Python bundle; builder inlines engine + runtime + provisioned broker/prefix/device (no WiFi secrets needed; loader establishes WiFi). App has its own MQTT client ID device+'-app-'+boot. OTA context unchanged {device,boot,sha256,loader,protocol,disarmed}. No hot patch to loader. No robot motion authorized in this turn; initial build MOTION_ENABLED=False. Explicit rejected motion result, not pretend execution. Status reports supported types, motion_enabled, armed=false, boot/build/digest. No arbitrary REPL or upload_code; unknown blocks reject before ANY execution.

## Ownership
engine firmware/robot_engine.py: pure cooperative Engine(io, clock) where clock has ticks_ms,ticks_diff; io.execute(type,params) -> result (instant start/display operations), io.stop(), io.read(sensor)-> value or raise. Public submit(program,run_id) returns acceptance object or raises ValueError; step() bounded per call; stop(reason='stop') cancels plan,io.stop; drain_events() list clears. Constructor motion_enabled=False. Validate whole recursive program max256blocks depth8 up front; supported explicit catalog; reject unsupported reporters/sensors/parameter errors. Events {run_id,event,block_path,type,details} accepted,started,completed,failed,canceled; no physical-success wording. Duration starts async once then next step checks expiry; no sleeps. Program max60sec deadline, max50loop iterations? bounded total runtime for forever, 1 dispatch perstep. Motion types require motion_enabled and arm flag Engine.arm() only allowed motionenabled; no auto arm. stop clears armed and pending. Allowed first release nonmoving wait,stop,display_text/say,set_led,set_variable/change_variable,math_operation,repeat,repeat_forever,if_obstacle/if_sensor_range/if_predicate/if_else_predicate,repeat_until/while_block/wait_until if confidently supported. Report exact supported list to runtime. Reporter math +,-,*,/,comparisons,boolean,var_get,sensor reads via io.read bounded. String literal vs var explicit. No native motor blocking turns: runtime rejects unsupported turn/melody commands rather than guessed alternatives. Existing catalog lacks capability negotiation, server must gate.

runtime firmware/robot_app.py: exports OTA_APP_PROTOCOL1,OTA_BUILD_ID,ota_init/ota_step. Imports RobotEngine from robot_engine; builder strips. Provision ROBOT_MQTT_BROKER,ROBOT_MQTT_PORT,ROBOT_TOPIC_PREFIX,ROBOT_DEVICE,MOTION_ENABLED constants prepended. Native hardware imports only inside ota_init. Use known imports mbot2/cyberpi/mbuild; no motion on init other than stop-only. own bounded mailbox and output queue; step connects/checks one msg, processes one request, advances engine once, publishes at most bounded events/telemetry each step. Publish robot/status legacy with status:'ready'/'running' plus application:'cooperative-v1',build,boot,sha256,motion_enabled,armed,capabilities; sensors preserve raw valid fields and errors (no manufactured sensor values). runtime telemetry every1sec and heartbeat2sec via ticks. Subscribe robot/program,command,emergency,config; emergency priority flag callback; no arbitrary exec/repl. Reject motion at submission while disabled. Commands/programs wrappers existing {command?} {type,params} and {program:[..],run_id?}; every request assigned/echoed run_id. Drop retained messages if library supports flag? classic callback no flag => do not claim protection; boot+run id gating server later. On errors stop and publish failure, don't swallow. Network disconnect stop/disarm and reconnect bounded2sec scheduling; native connect mayblock WDT remains ultimate. At OTA activate loader resets and startupstop.

Server integration parent: package builder reading sources and cfg generating no-key app. Integrate live status (runtime emits legacy status), gate sending motion if runtime motion_enabled false and supported catalog, preserve legacy compatibility. Expose no newly auto-running tasks. UI user-facing disarmed status and unsupported error, no auto reset/homing. Existing prepended default servo homing must be bypassed for cooperative app: capabilities says self_managed_homing true and no homing commands generated. No new calibration inference.

Tests: pure engine adapters explicitly not hardware simulation claims. Runtime mocked adapters software-only. Real device only actual telemetry and nonmoving wait/display/LED if desired plus rejection of motion (no physical test). Need prove OTA network stays active while long wait: status query during wait,stop interrupts,cancel outcome, next run works. Run lifecycle correlation stored. No release until failures addressed and actual candidate health/digest verified.
