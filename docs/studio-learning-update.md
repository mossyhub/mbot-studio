# Studio learning and interaction update

## Program editor

Existing blocks now move as their original rendered element during dragging. The browser's native screenshot ghost is suppressed; the source does not stay visible in its old position. Escape restores the original placement without editing the program. Valid drops retain block identities and use the existing nested/socket admission rules. The palette still creates new blocks.

## Challenges and achievements

The current curriculum offers 15 programming missions across Explorer, Builder and Inventor levels. Missions have unfinished starters, visible checklists, hints and a Program mission strip. Start Programming does not need an AI response.

Credit requires the exact submitted program and child profile, the server's matching compilation/source map, and a correlated whole-program completed event. Submission acknowledgements, starts, failures, cancellation, duplicate events, dead branches and zero-iteration loops are not completion. The browser cannot infer an earlier unrecorded run.

First Steps retains its historical ID and recognizes a total of at least 2 seconds of positive forward commands (up to 5), including bounded static repeats. Progress and old earned dates remain local to the child profile/browser. Historical awards must not be reinterpreted as proof of newly introduced criteria.

S1 elbow and M1 claw missions require the configured hardware and describe cautious, supervised command experiments. They do not claim measured joint angles, full claw travel or successful grasp. No cameras are required for programming credit; device completion is explicitly not physical accuracy evidence.

## Templates and Room Explorer

Eight finite examples use the installed AV runtime's supported values and commands. Nested hardware ports resolve from configuration. Movement examples make no calibrated-square/heading promises.

**Room Explorer is not an autonomous working program in this release.** Its old template requested unsupported live obstacle branches and an endless loop. It is now explicitly unavailable with an explanation rather than falsely labeled robot-ready. Line Follower and automatic Guard Robot have the same runtime limitation. These require a future cooperative live-sensor execution feature with its own bounded movement and safety validation; cached sensor snapshots are not a substitute.

## Verification

Regression tests use real React and Chromium, isolated server/firmware validators, source-map correlation and profile-scoped persistence. A nonmoving Hello, Screen mission was exercised through the candidate web application and real robot, and earned automatic credit only after matching device completion. Hardware motion trials and deployed revisions are recorded separately in acceptance evidence.
